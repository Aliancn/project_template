# tasks/ — 实验任务队列

借鉴 tasks.md 机制（github.com/tasksmd/tasks.md）的轻量实验队列：一个文件管队列、每任务一个子文件夹存详情、完成即整体存档。没有脚本工具，所有操作就是编辑文件和 mv。

## 结构

- `TASK.md` — 唯一队列文件：P0–P3 优先级分节 + checkbox 任务条目
- `<id>/` — 活跃任务文件夹：核心是 `design.md`（实验预注册），过程脚本/图表等产物也放这里
- `archived/<id>/` — 已完成任务文件夹的整体存档
- `archived/ARCHIVE.md` — 存档索引，一行一任务

优先级：P0 紧急（其他都停）/ P1 核心 / P2 有价值 / P3 备忘。节内越靠前越重要，新任务追加到节尾。

## 任务条目格式

TASK.md 只管排队：一行标题 + ID；设计/数据/测试对象/验收标准等具体内容全部写在 `tasks/<id>/design.md`。

```markdown
- [ ] 长序列批次的吞吐基准对比
  - **ID**: exp-longbatch-throughput
  - **Blocked by**: exp-xxx            ← 可选，多个用逗号分隔
```

- ID 必写：文件夹按 ID 命名、依赖按 ID 引用；kebab-case，一经分配不改名、不复用
- 认领：标题行尾加 ` (@名字)`，其他 agent 跳过已认领任务；放弃或完成时去掉
- 依赖：**Blocked by** 的 ID 还在队列 = 阻塞；ID 消失（已存档）= 自动解除

## 工作循环

入队 → 认领 → 执行 → 回填 → 存档，五步：

1. **入队**：与用户讨论清楚 设计/数据/测试对象 → 建 `tasks/<id>/design.md`（复制下方模板，填好除「结果」「结论」外的所有节）→ 在 TASK.md 对应优先级节**末尾**追加条目
2. **认领**：TASK.md 标题行尾加 ` (@名字)`；design.md 的 Status 改为 doing
3. **执行**：按 design.md 跑实验。启停遵守根 AGENTS.md Hard Rules 的审批分级（见该节两档清单）；过程脚本放任务文件夹，经验教训按根 AGENTS.md 约定记 devlog
4. **回填**：结果与结论写回 design.md 对应节；失败实验也要回填（负结果也是结果）
5. **存档**：design.md Status 改为 done → `mv tasks/<id> archived/<id>` → 从 TASK.md 删除整个任务块（元数据一起删）→ `archived/ARCHIVE.md` 表尾追加 `| 完成日期 | ID | 类型 | 标题 | 一句话结论 |`

队列空了或全部被阻塞时：向用户汇报并等待补充，不自造任务。

## design.md 模板

复制后填空；「结果」「结论」两节运行后回填：

```markdown
# <实验标题>

- **ID**: <id>
- **Type**: exp
- **Priority**: P1
- **Status**: todo
- **Created**: YYYY-MM-DD

## 背景与动机
<!-- 为什么做：回答什么问题 / 验证什么假设 -->

## 假设
<!-- 预期哪个可观测量怎么变、为什么；能写数值区间最好 -->

## 实验设计
<!-- 对照组 / 变量 / 关键配置；自变量只留一个，其余对齐 -->

## 数据
<!-- 数据集 / 规模 / 来源 / 预处理 -->

## 测试对象
<!-- 模型 / 实现 / baseline 列表（含版本或 commit） -->

## 测量
<!-- 可直接复制执行的测量命令 -->

## 判据
- **Success**: 达到什么数字算成功
- **Pivot**: 低于什么数字放弃这条路线

## 结果
<!-- 运行后回填：关键数字、图表/产物路径 -->

## 结论
<!-- 运行后回填：判断与下一步 -->
```

## 纪律

1. 没讨论清楚（设计/数据/测试对象缺一）不入队——先讨论，后落文档，再排队。
2. 结果未回填不存档；TASK.md 永远不留 [x]，完成即存档，历史查 git log 与 ARCHIVE.md。
3. 遵守 TASK.md 头部 `<!-- policy: ... -->` 策略。
4. 手动编辑 TASK.md 保持格式：元数据行 2 空格缩进 `- **字段**: 值`，多行值续行再缩进 2 空格。
