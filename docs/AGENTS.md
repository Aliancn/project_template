# 核心机制知识库（docs/）

存放**项目自身核心机制**的权威文档，形似 wiki：读一篇即可建立对某机制的稳定、完整认识。**长期有效、持续维护**，不是时点记录。

## 与其他目录的分工

- **`docs/`（本目录）**：项目自身机制的权威描述——机制怎么运作、关键不变量与契约束、跨文件的设计取舍；另收**冻结实验结果**（`experiment_result/`，稳定、可长期引用的结论页）。长期有效、可长期引用。
- **`research/`**：外部文献阅读、算法设计探索、对比研究。面向"别人怎么做 / 我们可以怎么做"。
- **`devlog/`**：时点性的开发过程记录（根因、修复、实验过程与原始数据、时间戳命名）。面向"当时发生了什么"。

同一机制若有 devlog 记录，沉淀稳定后**收敛进 `docs/`**，devlog 保留过程与证据链，`docs/` 只留权威结论并链接回 devlog。实验结论（矩阵/数字/判定）冻结后提炼进 `experiment_result/`（收录契约见该目录 `README.md`），来源必链 devlog 与代码版本。

术语与指代基准住在根 [`TERMS.md`](../TERMS.md)，本目录不单设术语页。

## 写什么

- **机制详情**：非显而易见子系统如何真正运作（数据流、控制流跨模块的衔接），超出代码与公开文档所能直接传达的部分。
- **不变量与契约**：组件之间的假设、时序保证，以及被违反时会怎样。
- **跨文件设计取舍**：需要综合多个文件才能还原的"为何如此设计"。
- **反复踩的坑**：已被重复犯错 ≥2 次的坑，集中固化。
- **冻结结论**：实验结果已稳定、可长期引用的矩阵/数字/判定 → `experiment_result/`（与"不写什么"里的过程数据区分，见该目录收录契约）。

## 不写什么

- **过程与原始分析**：属 `devlog/`，链接过去即可，不复制；实验**结论**经冻结后收 `experiment_result/`，原始过程仍留 devlog。
- **外部文献与算法探索**：属 `research/`。
- **代码会漂移的内容**：不整段复制代码；描述机制并指向源码符号或 `search for X`，不写死行号/易变路径。
- **上游工具文档**：外链，不转述。

## 组织约定

- **一页一主题**；宁可拆页，不写超长单页。
- **分类目录词表（封闭集合，与 README 板块一一对应）**：`docs/<分类>/<主题>.md`，snake_case 英文主题。新增页必须先从词表选分类；新分类先在词表和 README 各登记一行再建目录。**初始化时按项目研究脉络定义本项目词表**，示例：
  - `ours_method/` — 项目主线实现的机制（数据构造 / 调度 / 内存等）
  - `ref/` — 参考方法机制详解，文件名或主题含方法名
  - `analysis/` — 跨方法通用的机制与理论分析、工程机制（引擎 / 性能 / 显存）
  - `data/` — 验证数据构造（数据集、benchmark 配方）
  - `experiment_result/` — 冻结实验结论（**固定保留**；收录契约见目录内 `README.md`）
- **`README.md` 为唯一索引**：列出所有主题页与一句话摘要，板块标题后括注对应目录；新增页时同步更新。
- **互链**：同目录用文件名相对链接；跨目录用 `../<分类>/<页>.md`；不写仓库根绝对路径。
- **移动/改名四处同步**：`git mv` + README 索引链接 + 全库文内互链 + 本词表/板块描述；devlog 历史条目不改（当时路径为真），跨目录移动在 devlog 记录新旧对照。
- **语言**：中文为主，专有名词/代码符号/SOTA 术语保留英文（如 micro-batch、throughput、baseline）。
- **来源可追溯**：关键结论标注依据（源码 file:line、devlog、论文），便于核对。
- **同变更维护**：机制变更时，同一变更内更新对应的 `docs/` 页面。
- **页脚时间**：每页末尾一行 `Last updated: mm/dd/yyyy`，修改后同步更新。
