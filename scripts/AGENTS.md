# scripts/ — 实验与运维脚本规范

验证、基准、解剖、探针类脚本（`bench_*.py`、`debug_*.py`、`*_probe.py`、`*_autopsy.py` 等）遵循以下规范。

## 存放

- **按主题建子目录**：新主题在 `scripts/` 下新建文件夹（如 `scripts/train_bench/`），同一主题系列的脚本放在一起。不要把脚本堆在 `scripts/` 根目录，也不要把不同主题混进同一个文件夹。
- **每个主题目录一份 `README.md` 作索引**：脚本清单 + 一句话用途（有结论者写结论）；主题内的共用设施（公共 import、数据加载、计时设施）与 import 家族约束也写在这里，新增/移动/删除脚本时同步更新。

## 文件头格式

以 `#!/usr/bin/env python3` 开头；模块 docstring 用**中文标题 + 分节**，固定包含**目的**与**结论**，其余节按需取用：

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
<中文标题>
================

<一两句话：脚本做什么>

出处（可选）    对应论文 / 生产代码 file:line / 参考实现 / 姊妹脚本
目的（必填）    要回答的问题 / 验证的假设——为什么要写这个脚本
场景/方法（可选）ASCII 场景图、数学式、A/B/C 对照结构——具体到可画出来
判据（可选）    什么算过：精度预期（什么 dtype 下多少量级）、负对照（测试区分度）
运行（必填）    可直接复制执行的完整命令（含 ssh / env / 端口），含变体命令
结论（必填）    实际运行后的关键结果：数字与判断；每次重跑后回填更新
"""
```

分节标题用中文 + `----` 下划线，节顺序：出处 → 目的 → 场景/方法 → 判据 → 运行 → 结论。

## 正文注释风格

- **分节横幅**：大块代码用 `# ---` 横幅 + 中文小标题分节。
- **函数 docstring**：一行中文用途 + 关键张量 shape 标注（`x: [B,H,T,Dh]`）。
- **why 而非 what**：关键行注释解释为什么（如 `load-bearing: ...`），不复述代码。
- **发现的约束就地固化**：实验中发现的调度约束/数据陷阱（如"必须逆序接力""response_mask 不对齐 input_ids"）写在对应代码处，不只写 devlog。

## 维护纪律

- **结论必须回填**：跑完把关键数字/判断写进"结论"字段，重跑后结论变化要同步更新；不允许留空或过期。
- **本地为准**：本地 `scripts/` 是 source of truth，服务器副本只是运行态；本地改动后同步到服务器再跑。
- **文件头即索引**：打开脚本即可知道"它回答了什么问题、答案是什么"，不必重跑或翻 devlog。
